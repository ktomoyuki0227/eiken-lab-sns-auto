# X 予約投稿 実装計画

最終更新：2026-05-09
対象事業：The Rep English（TRE）から着手。その後 NES・AE へ展開。
決定経緯：LINEトーク（ともくん・中村くん・Asahi）での合意

---

## 方針サマリ

「毎日AIで生成して自動投稿」ではなく、
「2ヶ月分のコンテンツを一括生成 → Claudeのブラウザ操作でX予約投稿に一括登録 → 2ヶ月間は放置」という運用に切り替える。

理由：毎日異なる投稿を毎日生成する仕組みの完成度がまだ不十分なため、安定した運用を優先する。

---

## 仕組みの全体像

```
Step 1: コンテンツ生成
        Claude API（Difyとは別）で2ヶ月分（約60投稿）を一括生成
        ↓
Step 2: スプレッドシートへ格納
        TRE_X_Posts シートに投稿内容を貼り付ける
        ↓
Step 3: 中村さんレビュー
        フィードバック欄に確認・修正を記入してもらう
        ↓
Step 4: 予約投稿の一括登録
        Claude in Chrome でスプシを読み取りながら
        X の予約投稿UIに60件を一括登録
        ↓
Step 5: 放置（2ヶ月間、毎日予約投稿が自動で流れる）
        ↓
Step 6: 2ヶ月後に Step 1 から繰り返す
```

- X API（有料）は不使用。XのブラウザUIを直接操作する
- PCを常時起動する必要はない。予約投稿を登録してしまえばXが自動で投稿する
- ブラウザ操作は Playwright ではなく Claude in Chrome で行う（2ヶ月に1回の手動実行のため）

## Phase 1：コンテンツ生成の仕様

### 再利用する要素（workflow-tre.md / content-strategy-the-rep-english.md より）

X投稿の生成ルールはDifyのLLMプロンプトにすでに定義されている。
以下をそのまま流用する。

**投稿フォーマット**
- 140〜180字（日本語）厳守
- 冒頭1行：数字・損失フレーム・逆張りで即引き込む
  - 例：「TOEIC 700点取れない人の9割が、Part 7の解き方を間違えてます。」
- 本文：短い文を改行で区切り、テンポよく読めるようにする
- 語り口：効率・数字・断定（ビジネス層向け）
- リンクは末尾にまとめる（本文中にリンクを入れるとリーチが下がるため）
- 末尾の順番：エンゲージメント促進フレーズ → CTA誘導文 + URL → ハッシュタグ（一番下）
- CTA URL：https://the-rep-english.jp
- ハッシュタグ：最大3個

**コンテンツカテゴリ**（7種）
1. 解法系：Part別の爆速解法・時短テクニック
2. スコアアップ系：点数が伸びない原因と正しい対策
3. 時間管理系：本番の時間配分・タイムマネジメント
4. 教材選び系：単語帳・問題集の正しい使い方・選び方
5. メンタル系：試験当日の準備・集中力の保ち方
6. サクセスストーリー系：スコアアップ実績・合格体験談
7. 比較系：勉強法・教材・戦略の比較

**コンテンツの3大原則**
1. 損失回避：「知らないと損をする」「やらないと9割の人に負ける」
2. タイパ可視化：秒数・点数・時間などの数値で効率を見える化
3. 論理的断定：感情より根拠を優先する

**禁止事項**
- アスタリスク（*）不使用
- マークダウン記法不使用
- 180字を超えないこと

### 60投稿の内訳案（カテゴリ別）

| カテゴリ | 投稿数 | 備考 |
|---------|--------|------|
| 解法系 | 15 | 最も需要が高い |
| スコアアップ系 | 12 | |
| 時間管理系 | 8 | |
| 教材選び系 | 8 | |
| メンタル系 | 7 | |
| サクセスストーリー系 | 5 | |
| 比較系 | 5 | |
| 合計 | 60 | 2ヶ月分（1日1投稿） |

### スプレッドシートの格納先

SNS_history とは別に新規スプシを作成する。

シート名：`TRE_X_Posts`

| A列 | B列 | C列 |
|-----|-----|-----|
| No.（1〜60） | 投稿文（140〜180字） | フィードバック（中村さん記入欄） |

- Claude in Chrome がB列の投稿文を読み取って X に登録する
- 閲覧権限：「リンクを知っている全員」（Claude in Chrome からアクセスできるよう）

## Phase 2：予約投稿自動化の仕様

### Claude in Chrome の処理フロー

```
1. TRE_X_Posts スプシを開き、B列の投稿文を上から順に読み取る
2. X（ブラウザ版）を開く（ログイン済みの状態）
3. 以下を1件ずつ繰り返す：
   a. ポスト作成画面を開く
   b. 投稿文を入力する
   c. 予約投稿ボタンを押す
   d. 日時を設定する
   e. 予約を確定する
4. 60件完了後に終了
```

### 予約投稿の日時設定

- 投稿時刻：毎朝8:00 JST（中村くんと要確認）
- 開始日：コンテンツ生成・レビュー完了後、設定実行日の翌日から
- 終了日：開始日から60日後

## コンテンツ品質向上ロードマップ（中長期）

短期（今回）：2ヶ月分を一括生成して予約投稿

中期・長期（完成度が上がったら切り替え）：
1. スプシに過去の投稿内容を蓄積し、生成時に参照して重複を防ぐ
2. 他ユーザーの良投稿をリサーチしてベンチマーク（Apify連携を予定）
3. 月1でベンチマーク投稿を確認し、次サイクルの生成に反映する
